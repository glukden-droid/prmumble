1. ЧТО ЭТО
----------
Готовый к работе голосовой сервер для игровых серверов Project Reality: BF2.

  - mumble-server.exe : сервер Mumble 1.5.857, собранный из официальных
    исходников с небольшим патчем Project Reality. Патч заставляет его вести
    себя для клиента PR как старый PRMurmur 1.2, поэтому HUD в игре
    показывает, кто говорит (см. 13).
  - mumo + prbf2 : помощник, который переносит каждого игрока в канал его
    команды и отряда по данным клиента PR. Игроки сами каналы не выбирают.

Один сервер Mumble может обслуживать несколько игровых серверов: у каждого
свой набор каналов команд и отрядов.


2. ТРЕБОВАНИЯ
-------------
  - Windows 10 / 11 или Windows Server 2016 и новее, 64 бита.
  - Около 200 МБ на диске.
  - Ничего не нужно устанавливать: Python и все библиотеки внутри папки.
  - Порт 64740 TCP+UDP доступен игрокам (см. 6).
  - Игроки используют клиент Mumble из комплекта Project Reality
    (PRMumble, Mumble 1.3.0). Его запускает лаунчер PR.


3. ЧТО ЛЕЖИТ В ПАПКЕ
--------------------
  mumble-server.exe            голосовой сервер
  mumble-server.ini            настройки сервера (порт, приветствие, ...)
  MumbleServer.ice             файл интерфейса для mumo и скриптов
  games.txt                    ВАШИ игровые серверы - заполнить в первую очередь
  start.bat                    запускает сервер, затем mumo
  stop.bat                     останавливает оба
  setup-channels.bat           создаёт все каналы (один раз, при первом запуске)
  set-superuser-password.bat   задаёт пароль SuperUser (владельца)
  grant-bot.bat                даёт боту права во всех каналах
  check-acl.bat                показывает, что может подключённый игрок
  python\                      встроенный Python 3.11 с ZeroC Ice
  mumo\                        mumo, его настройки mumo.ini, модуль prbf2
  scripts\                     скрипты Python, которые вызывают .bat-файлы
  README_EN.txt / README_RU.txt   эта инструкция на английском и русском

Появляются во время работы:
  murmur.sqlite                база: каналы, пользователи, баны
  mumble-server.log            лог сервера
  mumo\mumo.log                лог mumo
  mumo\modules-enabled\prbf2.ini   карта каналов, её пишет setup-channels


4. УСТАНОВКА (ПЕРВЫЙ ЗАПУСК)
----------------------------
Распакуйте папку в постоянное место. Удобнее короткий путь, например
C:\PRMumble

Шаг 1 - перечислите свои игровые серверы в games.txt
  По одной строке на игровой сервер:

      имя | название канала | ip:порт

  имя              короткий идентификатор латиницей и цифрами, уникальный:
                   main0, main1
  название канала  что игроки видят в Mumble: [RU] Мой PR сервер #1
  ip:порт          адрес, по которому игроки заходят на ИГРОВОЙ сервер
                   (игровой порт, например 16567). Несколько адресов одного
                   сервера (внешний и локальный IP) - через запятую.

  Пример:
      main0 | [RU] Мой PR сервер #1 | 203.0.113.10:16567
      main1 | [RU] Мой PR сервер #2 | 203.0.113.10:16568

  ip:порт должен в точности совпадать с тем, что сообщает клиент PR, иначе
  игроков не будет переносить. Если не уверены - см. «Игроков не переносит
  по отрядам» в разделе 12.

  games.txt сохраняйте в кодировке UTF-8 (в Блокноте: «Сохранить как» ->
  кодировка UTF-8), если в названиях есть кириллица.

Шаг 2 - запустите сервер
  Запустите start.bat. Сервер стартует (в трее появится значок Mumble) и
  создаст пустую базу. Затем окно сообщит, что карты каналов ещё нет, и
  остановится - при первом запуске так и должно быть.

Шаг 3 - создайте каналы
  Не останавливая сервер, запустите setup-channels.bat. Он создаст:

      Root
        Lobby                       сюда попадают при подключении
        PR BF2 Game Servers
          <название канала>         по одному на строку games.txt
            Team 1                  (opfor)
              Commander, No Squad, Squad 1 ... Squad 9
            Team 2                  (blufor)
              Commander, No Squad, Squad 1 ... Squad 9

  и запишет mumo\modules-enabled\prbf2.ini (карту каналов для mumo).
  На сервере, где каналы уже есть, он работать откажется.

Шаг 4 - запустите всё
  Закройте окно start.bat, запустите stop.bat, затем снова start.bat.
  Теперь стартует и mumo и работает в этом окне.

Шаг 5 - задайте пароль SuperUser
      set-superuser-password.bat НадёжныйПароль
  SuperUser - учётная запись владельца (см. 8).

Шаг 6 - смените секрет Ice (рекомендуется)
  Секрет Ice защищает локальный интерфейс управления, через который
  работает mumo. Придумайте случайную строку и впишите ОДНО И ТО ЖЕ значение:
      mumble-server.ini   icesecretread= и icesecretwrite=
      mumo\mumo.ini       secret =
  Затем stop.bat и start.bat.

Шаг 7 - проверка
  Запустите Project Reality, зайдите на один из своих игровых серверов,
  откройте окно PR Mumble. Через несколько секунд вас должно перенести в
  канал вашей команды/отряда, и товарищи по отряду должны вас слышать.


5. ПОДКЛЮЧЕНИЕ ИГРОВОГО СЕРВЕРА И ИГРОКОВ
-----------------------------------------
Клиенты PR игроков должны подключаться к этому серверу Mumble: адрес этой
машины, порт 64740 - так же, как к вашему прежнему серверу Mumble.

Если нужен другой порт, измените port= в mumble-server.ini.

realityconfig_admin.py на игровом сервере: mum_mumbleSecret можно оставить
как есть. Проверка пароля identity PR на этом сервере выключена (в
prbf2.ini пустой secret), потому что клиент PR не передаёт совпадающий
пароль; старый PRMurmur тоже не мог его успешно проверить.


6. БРАНДМАУЭР
-------------
Откройте для входящих подключений:
      64740 TCP и 64740 UDP      (голос и управление)

НЕ открывайте 6504. Это интерфейс управления Ice, он слушает только
127.0.0.1 и должен оставаться локальным.

PowerShell (от имени администратора):
  New-NetFirewallRule -DisplayName "PR Mumble TCP" -Direction Inbound -Protocol TCP -LocalPort 64740 -Action Allow
  New-NetFirewallRule -DisplayName "PR Mumble UDP" -Direction Inbound -Protocol UDP -LocalPort 64740 -Action Allow

Если машина за роутером или файрволом хостинга, пробросьте / разрешите
тот же порт и там.


7. ЗАПУСК КАК СЛУЖБА WINDOWS
----------------------------
start.bat работает в окне консоли и останавливается при выходе из системы.
Чтобы сервер переживал перезагрузки и выход пользователя, используйте
один из вариантов:

Вариант А - NSSM (рекомендуется), https://nssm.cc
  nssm install PRMumble "C:\PRMumble\start.bat"
  nssm set PRMumble AppDirectory "C:\PRMumble"
  nssm set PRMumble AppExit Default Restart
  nssm start PRMumble
  Остановка:  nssm stop PRMumble   (затем stop.bat, чтобы точно
              завершить процесс сервера)

Вариант Б - Планировщик заданий
  Создать задачу:
    Общие:      «Выполнять для всех пользователей», «Выполнить с
                наивысшими правами»
    Триггеры:   При запуске
    Действия:   Запуск программы: C:\PRMumble\start.bat
                Рабочая папка:    C:\PRMumble
    Параметры:  снять «Останавливать задачу, выполняемую дольше ...»

В обоих случаях mumo останавливается, если сервер упал и start.bat
завершился; NSSM перезапустит его автоматически.


8. АДМИНИСТРАТОРЫ
-----------------
SuperUser
  Учётная запись владельца. Подключитесь любым клиентом Mumble (для
  администрирования лучше 1.4 и новее) с именем пользователя SuperUser и
  паролем из шага 5. SuperUser может всё; используйте его только для
  администрирования, а постоянным админам дайте свои учётные записи (ниже).

Добавление админов
  1. Будущий админ один раз подключается своим клиентом Mumble и
     регистрируется (правый клик по своему имени -> Зарегистрироваться).
  2. Под SuperUser: правый клик по Root -> Изменить -> Группы -> группа
     "admin" -> добавить зарегистрированного пользователя -> OK.
  Участники "admin" имеют все права везде (Write на Root): переносить и
  заглушать игроков, править каналы, слушать любой канал.

Бан, кик, перенос: правый клик по игроку в клиенте.


9. БОТЫ (ЗАПИСЬ, МУЗЫКА, РЕТРАНСЛЯЦИЯ)
--------------------------------------
Обычные игроки не могут входить в каналы команд и отрядов и слушать их.
Бота, которому это нужно, добавляют в группу "bots":

  1. Бот должен подключаться С клиентским сертификатом (подойдёт любой
     самоподписанный; создать можно так:
       openssl req -x509 -newkey rsa:2048 -nodes -keyout bot.key -out bot.crt -days 3650 -subj "/CN=MyBot"
     и указать bot.crt / bot.key в настройках бота).
  2. Пока бот подключён:
       grant-bot.bat MyBot
     Скрипт зарегистрирует бота по сертификату и добавит его в "bots".
  3. Переподключите бота.

После этого бот может входить в любой канал, слушать (функция «слушать
канал» в Mumble 1.4+), говорить, шептать, писать в чат и заглушать других.
mumo ботов не трогает: у них нет игрового контекста PR.


10. ПОВСЕДНЕВНАЯ РАБОТА
-----------------------
  Запуск:            start.bat  (или служба)
  Остановка:         stop.bat   (или остановка службы)
  Кто что может:     check-acl.bat ЧастьНика
  Логи:              mumble-server.log, mumo\mumo.log
  Подробнее о mumo:  в mumo\mumo.ini поставьте  level = 10  (в лог пишется
                     каждый перенос), перезапустите mumo; потом верните 30,
                     на полном сервере лог растёт быстро.

Нормальные строки в логе, это НЕ ошибки:
  "<игрок> not allowed to Enter in Squad N"
      Клиент PR сам пытается войти в свой отряд, сервер отказывает, и
      через мгновение mumo переносит игрока.
  "Zeroconf ..."           безвредно.

Добавить игровой сервер позже: setup-channels.bat работает только на
пустом сервере. Либо начните заново (см. 11, «Начать заново»), либо
создайте каналы клиентом админа и вручную добавьте секцию [gN] в prbf2.ini
(скопируйте существующую и поменяйте номера каналов, name и ipport_filter).


11. ОБНОВЛЕНИЕ, РЕЗЕРВНАЯ КОПИЯ, ПЕРЕНОС НА ДРУГУЮ МАШИНУ
---------------------------------------------------------
Резервная копия
  Остановите сервер и скопируйте:
      murmur.sqlite, mumble-server.ini, games.txt,
      mumo\mumo.ini, mumo\modules-enabled\prbf2.ini
  В базе хранятся каналы, зарегистрированные пользователи, админы и баны.

Обновление на новый пакет
  stop.bat, распакуйте новый пакет в НОВУЮ папку, скопируйте в неё пять
  файлов выше, start.bat. setup-channels.bat не запускайте - каналы уже
  есть в murmur.sqlite.

Перенос на другую машину
  Так же, как обновление. Регистрации игроков сохраняются; если не
  скопировать murmur.sqlite, игроки один раз увидят предупреждение о
  сертификате (сертификат сервера хранится в базе).

Начать заново (новые каналы)
  stop.bat, удалите murmur.sqlite и mumo\modules-enabled\prbf2.ini, затем
  раздел 4 начиная с шага 2. Регистрации, админы и баны пропадут; ботам
  нужно снова выдать права.


12. РЕШЕНИЕ ПРОБЛЕМ
-------------------
start.bat: "The server did not open its Ice port"
  - Смотрите mumble-server.log.
  - Порт 64740 или 6504 занят другой программой (например, старым Murmur):
      netstat -ano | findstr "64740 6504"
  - Опечатка в ini; причину сервер пишет в лог.

Окно mumo закрывается / в mumo.log "Server refused connection"
  Порт или секрет Ice в mumo\mumo.ini не совпадает с mumble-server.ini
  (строка ice= и icesecret*). Сделайте их одинаковыми.

Игроков не переносит по отрядам
  1. Поставьте level = 10 в mumo\mumo.ini, перезапустите, дайте игроку
     зайти, посмотрите mumo\mumo.log.
  2. Строка "No matching game found" или после строки с контекстом игрока
     ничего нет: ip:порт, который сообщает клиент, отличается от games.txt /
     ipport_filter в prbf2.ini. В строке с контекстом - строка base64;
     раскодируйте её (например, в PowerShell:
       [Text.Encoding]::UTF8.GetString([Convert]::FromBase64String("<текст>"))
     ) - внутри {"ipport":"x.x.x.x:порт"}. Впишите ровно это значение в
     ipport_filter нужной секции [gN] в prbf2.ini (несколько значений через
     запятую) и перезапустите mumo.
  3. "Failed verifying identity": в prbf2.ini непустой secret. Сделайте
     "secret =" (пусто) и перезапустите mumo.

Игроки не могут говорить / микрофон показан заглушённым сервером
  - В канале игрового сервера (над Team 1/2) говорить нельзя: туда mumo
    выводит игроков, вышедших из игры.
  - Проверьте, что в prbf2.ini пустой secret (см. выше).
  - Переподключение клиента PR Mumble обновляет то, что он показывает.

HUD не показывает, кто говорит
  - Убедитесь, что запущен ИМЕННО этот mumble-server.exe (у обычного
    сервера Mumble нет патча PR). mumble-server.log начинается с
    "Murmur 1.5.857 running on ...".
  - Для местного (близкого) голоса HUD показывает только игроков в пределах
    примерно 70 м - это правило лаунчера PR.

Предупреждение клиента PR о «слушателях канала»
  Ожидаемо: слушатели включены для ботов и админов. Чтобы убрать
  предупреждение (вместе со слушателями), поставьте listenersperchannel=0
  и listenersperuser=0 в mumble-server.ini и перезапустите.


13. ТЕХНИЧЕСКИЕ ПОДРОБНОСТИ
---------------------------
Патч PR (накладывается на исходники Mumble 1.5.857):
  - plugin identity каждого игрока отправляется остальным клиентам, в том
    числе в списке пользователей при подключении (обычный Mumble держит её
    только на сервере). Из неё клиент PR берёт игровой ник для HUD.
  - Поле 20 сообщения UserState - "repeated float position", как в
    PRMurmur; клиент PR отправляет туда свою игровую позицию, сервер
    пересылает её - в отличие от PRMurmur только в канал отправителя и
    связанные с ним (его команде), противники её не получают (нет радара
    для изменённых клиентов). В обычном 1.5 поле 20 занято
    temporary_access_tokens; они перенесены на поле 120 (клиенты PR их
    не отправляют).
  - Контекст плагина (адрес игрового сервера), как и в PRMurmur, другим
    клиентам не отправляется.

mumo/prbf2 (модуль PR, перенесённый на Python 3) также обходит особенность
Mumble 1.5, из-за которой при смене групп сервер сообщал клиентам, что
игрок заглушён: группы меняются только при реальной смене команды, отряда
или роли, а после каждого переноса отправляется правильное состояние
«заглушён/не заглушён».

Ice: 127.0.0.1:6504, используют mumo и скрипты. Сервер 1.5.857, Python
3.11, ZeroC Ice 3.7.
